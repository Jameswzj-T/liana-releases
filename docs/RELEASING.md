# 发布要求

源码可编译与安装包可公开分发是两道检查。

## 源码

- 逐项核对公开文件清单，只包含产品源码、合成测试、文档、图标与许可证。
- 不带真实 Key、用户设置、音频、历史、日志或个人开发记录。
- 不把曾含私人资料的仓库及其 Git 历史直接改成公开。
- 离线测试通过，记录实际测试范围；不将模拟测试表述为真机验收。

## 安装包（RC3 已发布，RC4 已在本地生成、未上传）

现有 RC3 历史发布保留。RC4 仅准备临时签名的早期预览包，不冒充 Developer ID 签名、公证或新机器已验收的正式发行版；上传和发布仍是单独操作。下面列出正式分发要求。

- 使用可追溯的源码和锁定依赖，收齐解释器、依赖和模型的许可证/NOTICE。
- 验证包内仅含支持的运行依赖、固定模型与资源，不夹带开发环境或用户数据。
- 对可执行代码进行适当的 Developer ID 签名，完成 Apple 公证并验证 Gatekeeper。
- 检查首次安装、升级、钥匙串授权、麦克风/辅助功能权限以及退出重开。
- 在目标 Mac 上验证本地听写、可选云端开关、失败时保留文字和光标处输入；付费测试须由测试者知情开启。
- 提供版本、校验值、已知限制和更新说明。

普通用户不应被要求关闭系统安全保护来安装正式发行版。不要用临时签名的开发产物代替完成上述检查的安装包。

## 本地预览包构建

当前预览组装器明确复用一个已经审计过的本地 Liana.app 中的 Python 运行时、模型和第三方许可证；不会从该 App 复制产品源码、旧发布元数据、录音或用户数据。产品源码必须来自当前干净提交，依赖版本与模型 SHA 必须匹配本仓库锁文件。该步骤不下载依赖、不访问 Key，也不启动或覆盖原 App。

```sh
python3.12 scripts/package_preview.py \
  --runtime-app /path/to/trusted/Liana.app \
  --output-dir /path/to/new-rc4-directory
```

已有输出目录会被拒绝。脚本重新编译外壳、检查搬迁与原生库路径，对新包临时签名，检查 ZIP 和隐私边界，并生成 SHA256SUMS。原始本机审计报告在包外，不作为上传附件。它不是从零下载的完整供应链重建工具；运行时来源必须先独立核对，不能使用来路不明的 App。

还须在包外用明确合成的语音完成离线模型检查，然后在目标设备验证安装、授权和真实输入。打包通过不会自动生成 Git 标签、推送源码或上传 Release。
